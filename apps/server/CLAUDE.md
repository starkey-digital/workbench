# workbench-server (`src/`)

`workbench-server` (lib + bin). axum control plane; **no tauri**.

- `lib.rs` — `app()` (router + auth + CORS), `serve()` (standalone, own managers), `spawn_embedded(bind, port, Managers, token: String)`/`ServerHandle` (desktop; token is mandatory and must pass `token::is_strong`, so an embedded listener can't be unauthenticated). **`ServerHandle::stop()` revokes**: each listener's `AppState.revoked` watch flips, and every terminal WS attached through it gets `{"t":"revoked"}` + close — upgraded sockets outlive axum's graceful shutdown and the token is only checked at upgrade, so without this a phone kept typing after server mode was turned off or the token rotated. The loopback listener has its own signal; terminals stay alive for other listeners. Clients show closed/ended (not "Take control") on `revoked`. `stop()` waits at most `STOP_DEADLINE` (5s) for open requests, then aborts the server task and returns, so the desktop's `lan` lock (and Settings) never hangs on a client that stopped reading (the listener is closed; axum's per-connection tasks are out of reach and finish on their own). CORS allows any origin but only `Authorization`/`Content-Type` and no credentials mode — safe only because auth is a bearer header, never a cookie.
- `routes.rs` — control-plane endpoints (1:1 with core ops): `GET /projects`, `POST/PUT/DELETE /projects` (the phone's one-project add/edit/remove, `workbench_core::projects`; a rename sends the workspace `UpdateProject`, a remove `CloseProject` first; each bumps `Managers.projects`, which the desktop turns into `projects:changed` and reloads), `GET /fs/folders?path=` (subfolders for the phone's folder picker; home without `path`), `GET/POST/DELETE /projects/worktrees`, `GET /projects/branches`, `GET /projects/git-info`, `GET /projects/git-{status,diff}` (git review), `GET /projects/github-remote` (`null` without a GitHub `origin`), `GET /sessions/{claude,codex}`, `GET /settings/{claude,workbench}`, `PUT /settings/sync` (501 stub seam), `PUT /settings/active-claude-account` (`claude_accounts::set_active`, the phone's account switcher), `GET/POST /host/update` (host version/update; POST answers 202 then installs and restarts; 501 without `Managers.host`, i.e. standalone), `GET /remote/terminals` (list) and `GET /remote/terminals/:id/ws` (attach), `POST /workspace/commands` + `GET /events/workspace` (the workspace service, the only way to start or end a terminal or chat; see "Workspaces are the server's"), `GET /health` (`workspaceApi: 1`; the phone refuses a host without it), `GET /` (built-in page: projects, worktrees, create a worktree)
- `agent.rs` + `agent/` + `agent_routes.rs` — chat sessions for Claude and Codex. `AgentManager` owns ids/aliases, the lifecycle lock, the cap and process groups; `agent/driver.rs` is the per-CLI part. Codex = one `codex app-server` per session. Claude = an interactive `claude` in a server terminal, made a chat by the Workbench plugin over `/mod/*` (`agent/modlink.rs`, `mod_routes.rs`). WS `/agent/{claude,codex}/:id/ws`: snapshot, then coalesced updates; rewind, mode and account switches restart the terminal under the same id. Started and ended only by workspace effects. **Read `docs/CHAT.md` §Server before touching any of it.**
- `workspace.rs` + `workspace/` — `WorkspaceService` in `Managers`: owns the workspace model (`POST /workspace/commands`, `GET /events/workspace` snapshots with per-pane runtime), runs its effects through the terminal/chat managers (`exec.rs`), folds attach/re-key/exit/busy back (`fold.rs`; a pane with a spawn still queued (`PaneRuntime::spawns`) is left alone, since its old process may still report), boots saved panes when the first listener binds (a v2 file, else the old `workspaces.json` migrated). A `Stop`/`End` finds the pane's terminals when its worker runs it (`TerminalManager::pane_terminals`), not when it was queued, so a second Restart before the first lands stops what that one started; a panicking effect is logged and its pane's worker carries on. `persistent()` (the binary and the desktop's `ServerControl`) saves `workspaces.v2.json` under an OS file lock (`workspaces.v2.lock`, `File::try_lock`; the kernel drops it when the process ends, so no stale pid can lock the next launch out; a filesystem without locks saves unlocked); `Managers::default()` is in-memory, so tests never touch a real config dir. Desktop and phone both render it. See `docs/WORKSPACE_MODEL.md`.
- `attention.rs` + `attention_feed.rs` — shared notification transitions and bounded event history. Claude plugin and Codex stream/notify updates publish directly; desktop subscribes and Android long-polls the same cursor feed.
- `auth.rs` — bearer-token middleware (`/`, `/health`, `/mod/*` (each checks the terminal's own token; served only by the listener `WORKBENCH_MOD_URL` names, `AppState.local_port == mod_port()`, 404 on a LAN listener), `/events/workspace` (EventSource can't send headers; checks `?token=` itself via `token_ok`) and the terminal WS path exempt — the WS checks `?token=` itself; constant-time compare; no-op only for a tokenless standalone server) + `ws_origin_allowed`: the terminal WS upgrade rejects any `Origin` other than the Tauri webviews (`tauri://localhost`, `http(s)://tauri.localhost`), the server's own page (origin == `Host`), or — debug builds only — the Vite dev servers on 1420/1430. Native clients send no `Origin` and pass.
- `error.rs` (`ApiError`: anyhow→HTTP), `state.rs` (`AppState`, `Managers`), `cli.rs` (clap + `resolved_token` start-up guard)
- Binds `0.0.0.0` with a required token; traffic is plaintext HTTP, so still keep it on a private network (Tailscale). `GET /settings/workbench` redacts `serverToken`, and spawned shells get `WORKBENCH_TOKEN` stripped from their env.
