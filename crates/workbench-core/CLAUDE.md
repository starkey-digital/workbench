# workbench-core

Pure, non-Tauri logic reused by the desktop and the server. Never add `tauri` here.

## Modules

Pure, non-Tauri logic reused by desktop and server. All `Serialize`/`Deserialize`, all return `anyhow::Result`:

- `types.rs` — Shared serde types (`ProjectConfig`, `CreateWorktreeRequest`, `WorkbenchSettings`, workspace snapshots, GitHub/Trello types). The single wire contract for both Tauri IPC and the server's JSON API (`#[serde(rename_all = "camelCase")]`).
- `config.rs` — Project/workspace/settings persistence (`~/.workbench/`)
- `projects.rs` — one-project add/edit/remove for remote clients (`POST`/`PUT`/`DELETE /projects`; the desktop saves its whole list), serialized load-modify-save, refusals as `projects::Invalid` (400); `list_folders` lists a host folder's visible subfolders (`GET /fs/folders`) for the phone's folder picker
- `git.rs` — Git CLI wrappers: branch info, worktree CRUD, branch listing
- `worktrees.rs` — the one worktree create/remove behind both the Tauri commands and `POST`/`DELETE /projects/worktrees`: the repo must pass the cwd allowlist, and a create fills an unset strategy/start point/fetch from the host's settings and always computes the path from the layout (`CreateWorktreeRequest` has no `path`; an older client's is ignored), so clients send only the branch and per-call picks (copy options); remove checks registration and lists worktrees once, deletes the branch on `deleteBranch` and answers `{branchDeleted}` (a client seeing no such field, an older host, deletes the branch itself).
- `cwd.rs` — `resolve_cwd`, the cwd allowlist (a registered project or a known worktree of one) for pane spawns, `/agent/files`, git review and worktree changes; a refusal is `cwd::NotAllowed`, which the server's `ApiError` answers with 403. The server re-exports it as `crate::cwd`.
- `claude_sessions.rs` / `codex_sessions.rs` / `codex_config.rs` — session discovery (`~/.claude/`, `~/.codex/`)
- `claude_launch.rs` — builds every Claude terminal command (every pane is a server terminal), so no client can skip the sandbox or permission mode: `startup_command(command, claudeSession)` (not both) → `terminal_command` (`--resume`/`--session-id`, permission mode, srt wrapper failing closed without its settings file, a new session's `prompt` after `--`; Windows drops an unsafe prompt, `prompt_notice` says why: the workspace exec puts it in the pane runtime's `notice`, cleared by the next spawn, and each client shows it once per spawn (`paneNotices` in `@workbench/types`; desktop toast, phone notice)). Holds the `SANDBOX_RUNTIME_PACKAGE` pin and trust-dialog helpers.
- `claude_transcript.rs` (+ `claude_transcript/`) — folds Claude session JSONL (history) and the plugin's stream-json lines into chat `TranscriptItem`s (approvals, elicitations, events, artifacts, goals, rewind branches). Details: `docs/CHAT.md` §Transcript.
- `codex_transcript.rs` (+ `codex_transcript/`) — folds `codex app-server` JSON-RPC notifications and server requests into the same `TranscriptItem`/`TranscriptMeta` (a command is `Bash`, a file change `Write`/`Edit` with hunks, the plan `TodoWrite`, a question `AskUserQuestion`, an MCP elicitation the same `Elicitation` item as Claude's), so one chat view renders both CLIs. Approvals answer the JSON-RPC request; Always allow is offered only when codex offers `acceptForSession` (never the execpolicy amendment — that saves a lasting rule); deny is `decline`, else `cancel` (ends the turn). Unservable requests get an immediate error/decline (unanswered, codex waits forever). `fixtures/app-server-0.159.3.jsonl` is a recorded real turn; regenerate shapes with `codex app-server generate-ts --experimental`; see `docs/CODEX_IMPLEMENTATION.md`.
- `settings.rs` — Claude Code settings CRUD, plugin/skill/hook discovery
- `github.rs` — GitHub CLI wrappers
- `package_scripts.rs` — root `package.json` reader for the Scripts tab: package manager from `packageManager`, then lockfile, then npm; scripts in file order (custom visitor, since `serde_json` maps sort); script names with shell-special characters are dropped because they're typed into a shell as `<pm> run <name>`
- `trello/` + `trello_automation.rs` — Trello API integration (async; uses a self-built Tokio runtime, no Tauri)
- `chat_attachment.rs` (a dropped chat file → image / PDF / text attachment; limits shared with the server), `project_files.rs` (the `@` mention file list)
- `claude_plugin.rs` — embeds `plugins/workbench` and writes it to `~/.workbench/claude-plugin/workbench`; `plugin_dirs_env()` + `WORKBENCH_HOOK_SOCKET` wire every shell and chat to it; `shell::scrub_inherited_env()` drops a parent Workbench's wiring; the old marketplace install is removed at startup. Details: `docs/CHAT.md` §Plugin.
- `pty.rs` — `pty::spawn(&pair, cmd)` starts every terminal shell (server terminals, macOS native terminals) without forking: Linux `posix_spawn` with `POSIX_SPAWN_SETSID` + opening the slave in the file actions (glibc's setsid runs first, so that open makes it the ctty); macOS spawns `pty_exec.c` (built by `build.rs`, embedded, written to `~/Library/Caches/workbench/workbench-pty-exec-<hash>`) which calls TIOCSCTTY and execs the shell, because XNU runs file actions in the parent's context and never grants a ctty there (bash reopens its tty and gets one anyway, zsh doesn't and loses job control). Windows keeps portable-pty's ConPTY spawn. Old glibc (no `addchdir_np`/SETSID) or a shim that cannot be installed falls back to portable-pty (fork) with a warning. A bare program name is looked up on the command's PATH only, never in the cwd
- `workspace/` — the shared workspace → tab → pane model (`model.rs`), its commands/effects (`command.rs`), every rule as pure `ops::apply` (`ops/lifecycle.rs`: resume dedupe, one pane per session, `/clear` re-key, restart, one-shot prompts, Codex mode; `ops/layout.rs`: labels, split/move) and `persist.rs` (`workspaces.v2.json`, migrating the old `workspaces.json`, which it never writes so older builds keep working); run by the server's `WorkspaceService` (below); See `docs/WORKSPACE_MODEL.md`. `codex_launch.rs` builds a Codex TUI terminal's `codex` command from the saved settings, as `claude_launch` does Claude's.
- `transfer/` — copying a project to another host: `project` packs the whole folder minus git-ignored rebuildable dirs (`node_modules`, `target`, …) and `.worktrees`; `claude` packs `~/.claude`'s CLAUDE.md, settings, skills, agents, commands, hooks and `.claude.json` `mcpServers` (plus account dirs) and merges them there without overwriting, moving paths under the sender's home to the receiver's; logins never travel; `send` streams the pack into the upload (desktop `copy_project_to_server`).
- `paths.rs` (`atomic_write`), `session_utils.rs`, `shell_integration.rs`, `token.rs` (CSPRNG bearer tokens + `is_strong`, ≥32 chars), `net.rs` (`pairing_addresses`: IPv4 via `if-addrs`, confirmed-Tailscale first, then RFC 1918; 100.64/10 is also carrier-grade NAT, so it counts as Tailscale only with a Tailscale-named interface or a `tailscale ip -4` match — macOS `utunN` needs the CLI)

Desktop re-exports every core module at its crate root (`pub use workbench_core::{config, git, types, …}` in `lib.rs`) so `crate::config`, `crate::types`, etc. resolve unchanged across the desktop code — only the re-export line changes when moving logic to core.
